# MonDex public product website

## Scope and mode
Persuade / interactive product experience. German public landing page, separate from the native MonDex app. User supplied a fully specified visual direction and exact section order; build directly from that pinned brief, no alternative concept round.

## Audience and success
Pokémon TCG collectors deciding whether MonDex fits their collecting ritual. Success: switch phone previews, reveal Mew, open and browse a binder, try a scan reaction, reach the launch form.

## First viewport
1200px centered width; 72px sticky header, original Orbit brand. Left: exact headline “Deine Karten. Dein MonDex.” at 64–72px, explanatory copy, launch CTA and preview anchor. Right: one straight 320px phone containing a real stateful preview. Neutral black ground, no glow, no decorative floats, no added typeface. Mobile stacks at 20px margins.

## Signature moments
Discovery scan resolves a silhouette in 760ms and shares counters with the Hero. Binder covers are actual CSS objects with restrained thickness; 600ms hinge opening, 360ms pages, stable scene height. Scanner runs Standard, Holo or Metallic only on explicit click; cancellable timers and no audio/camera.

## Content and states
Exact user copy takes precedence. All numbers are examples. Full-art cards use labeled stylized effects, not authentic foil claims. Launch is an honest local validation demo with no network or storage. Contact/legal information remains explicitly unfinished. Preserve existing asset provenance, centralize asset paths and demo data. No extra native app changes or deployment.

## Verification
360, 390, 768, 1024, 1440, 1920px plus 1280px browser viewport. Keyboard navigation, dialog focus return, Escape, all demo states, repeat/reset/cancel, no-JS content, reduced motion, production build, TypeScript, lint. One batched inspection, one confirmation after material fixes. Assets must all load and image dimensions stay stable.

## Remaining launch inputs
Actual waitlist endpoint, operator/contact/legal texts, final public-use asset clearance. Existing repo images are reused for the prototype; provenance does not assert an independent publication license.
